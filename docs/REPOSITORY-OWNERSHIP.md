# Repository Ownership Boundaries — Omran Store

**Status:** Controlled / read-first
**Evidence snapshot:** 2026-10-06 UTC

These boundaries assign source and approval responsibility; they do not grant the editing agent authority to change production systems. Where an owner or private repository has not been independently identified, this document explicitly leaves that ownership unresolved rather than guessing.

| Boundary | Authoritative location / owner | Non-owner and safeguards |
|---|---|---|
| **Store source** | GitHub `alaaomran2020/omran-store-live`, protected `main`. | Cloudflare Pages, GitLab copies, AI systems, local worktrees, and generated build output are not canonical source. Changes use a reviewed branch/PR and the repository governance process. |
| **Product source** | `public/catalog/products.csv` in the canonical repository; its approved build-time snapshot is generated by the documented build workflow. | GitLab copies, AI output, external operational tools, and runtime state do not supersede this source. Product records and identifiers are protected. This governance documentation does not edit the catalog or generated product data. |
| **Product media** | Product assets and references in the canonical repository, including the documented same-origin product media directories; the existing product/media resolver and deployment integrity gates govern their use. | No media-reference, resolver, URL, or binary changes are authorized by this documentation task. Cloudflare is the serving layer, not the owner of media source records. |
| **Private operational data** | No separate private data repository or owner-approved private data source was verified in this inspection. Sensitive operational records remain with the explicitly authorized business system and its designated human owner. | Do not infer that this public repository or either GitLab project is a private-data store. Do not copy private data, credentials, customer records, or operational exports into documentation. Unclear ownership is a STOP condition. |
| **AI execution** | Human-approved operators own decisions. ChatGPT, Arena, Gemini, AlphaCode, and other AI systems may execute only within the access tier and branch assigned to them. | AI systems do not own source, product facts, credentials, canonical status, approvals, or deployment authority. They are optional and must not be a runtime dependency. |
| **Automation** | The canonical repository owns its tracked automation code. `.github/workflows/deploy-storefront.yml` is the approved production deployment workflow; other automation is subordinate to the boundaries it serves. `package.json` contains a local `pnpm deploy` Wrangler command, but its presence does not grant production authority. | The separate GitHub repository `alaaomran2020/omran-toys-automation` is classified as development/operations, not Store source or deploy authority. Automation cannot independently approve protected actions or promote data. |
| **Cloudflare production** | Cloudflare Pages project `omrantoys-live-app` serves the production site at `omrantoys.store`; the production workflow publishes validated output from GitHub. Cloudflare configuration and DNS remain under the authorized Cloudflare account owner. | Cloudflare output/configuration does not become source code or product-data authority. No Cloudflare, Pages, domain, DNS, token, or configuration change is authorized here. |
| **GitLab mirrors** | GitHub `main` owns canonical content. GitLab `omran-toys-company-group/omran-store-live` (declared project ID `87219545`) is a mirror by designation; `adreanolomran/omran-store-live` (ID `87219408`) is a duplicate/removal candidate. | Neither GitLab repository is Production Source of Truth. The group project could not be independently inspected without GitLab access; the duplicate was publicly inspectable and behind GitHub `main`. Do not modify the mirror or remove either repository without explicit human approval. |

## Ownership escalation

If a change crosses one of these boundaries, pause and obtain explicit approval from the accountable human owner before implementation. A technically writable repository, valid credential, successful automation run, or AI recommendation does not transfer ownership.
