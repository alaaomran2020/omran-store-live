# OMRAN TOYS — إدارة المنتجات من Google Sheets

> منتج جديد على الموقع في أقل من دقيقتين، من الهاتف، بلا GitHub ولا Deploy ولا
> مفاتيح API ولا قاعدة بيانات ولا لوحة تحكم.

```
📱 موبايل → 📸 صورة المنتج بالـAI → ☁️ Google Drive → 📊 Google Sheets → 🌐 omrantoys.store → ☁️ Cloudflare
```

---

## 1) شكل الـGoogle Sheet

ورقة واحدة، الصف الأول عناوين الأعمدة، بهذا الترتيب بالضبط:

| id  | name             | price | category | description                            | image      | active | sort_order | product_prompt   | workflow_status | qa_status | created_at | updated_at |
| --- | ---------------- | ----- | -------- | -------------------------------------- | ---------- | ------ | ---------- | ---------------- | --------------- | --------- | ---------- | ---------- |

> ⚠️ **بوابة النشر (من 2026-09-03):** الظهور العام يتطلب صراحةً
> `active=TRUE` + `workflow_status=PUBLISHED` + `qa_status=PASS` — أي مفتاح
> غائب يعني أن المنتج **غير منشور** (Fail-Closed). التفاصيل الكاملة:
> `docs/PUBLICATION-GATE.md`.
| 001 | سيارة أطفال سباق | 250   | سيارات   | سيارة أطفال بتصميم رياضي وألوان جذابة   | IMAGE_URL  | TRUE   | 1          | PRODUCT_PROMPT   |

قواعد كل عمود (كلها متسامحة — لا شيء يكسر الموقع):

| العمود           | مطلوب؟ | السلوك                                                                                    |
| ---------------- | ------ | ----------------------------------------------------------------------------------------- |
| `id`             | لا     | معرّف المنتج. لو فارغ يُولَّد من رقم الصف. المكرر يُصحَّح تلقائيًا.                          |
| `name`           | **نعم**| اسم المنتج، وهو نفسه المستخدم في رسالة واتساب. الصف بلا اسم يُتجاهل بصمت.                   |
| `price`          | لا     | رقم فقط أو مع عملة: `250` / `1,250.5` / `٢٥٠` / `250 ج.م`. أي قيمة غير صالحة → «للاستفسار والكميات». |
| `category`       | لا     | يظهر كشارة على البطاقة، ويصنع رقائق الفلترة تلقائيًا. الفارغ = بلا تصنيف.                    |
| `description`    | لا     | وصف قصير على البطاقة وكامل في نافذة التفاصيل.                                               |
| `image`          | لا     | رابط صورة (Google Drive أو أي رابط https). الفارغ/المكسور → لوحة بديلة بهوية الموقع.        |
| `active`         | لا     | `TRUE` يظهر، `FALSE` لا يظهر للزوار إطلاقًا. **الفارغ = يظهر.**                              |
| `sort_order`     | لا     | ترتيب تصاعدي (1، 2، 3…). الفارغ يأتي بعد المرقَّمة بترتيب الشيت نفسه.                        |
| `product_prompt` | لا     | تشغيلي فقط: برومبت تجهيز الصورة بالـAI. **لا يُعرض للزائر أبدًا.**                            |

نموذج جاهز للنسخ: [`docs/sample-products.csv`](./sample-products.csv) — افتحه في
Google Sheets عبر `File → Import → Upload` لتحصل على الأعمدة بترتيبها الصحيح.

> 🤖 **إضافة المنتجات آليًا من Telegram**: توجد Pipeline جاهزة
> (Telegram → n8n → AI → Drive → Sheets → موافقة → الموقع) تكتب في نفس هذا
> الشيت وتحترم نفس الأعمدة — انظر [`docs/N8N-PRODUCT-PIPELINE.md`](./N8N-PRODUCT-PIPELINE.md).
> الأعمدة الإضافية التي تستخدمها (`workflow_status`, `created_at`, `updated_at`)
> تشغيلية فقط ويتجاهلها الموقع تمامًا.

## 2) نشر الشيت كـCSV (مرة واحدة فقط)

1. افتح الشيت → **File → Share → Publish to web**.
2. في القائمة الأولى اختر **الورقة** التي تحتوي المنتجات (لا «Entire document»).
3. في القائمة الثانية اختر **Comma-separated values (.csv)**.
4. اضغط **Publish** ثم **OK**، وانسخ الرابط. شكله:

```
https://docs.google.com/spreadsheets/d/e/2PACX-xxxxxxxxxxxx/pub?gid=0&single=true&output=csv
```

> الرابط عام للقراءة فقط، وليس مفتاح API. لا تحتاج Google API ولا OAuth ولا
> Service Account. إن نسخت بالخطأ رابط التحرير (`…/edit#gid=0`) فالموقع يصلحه تلقائيًا.

---

## 3) أين تضع رابط الـCSV

**الطريقة الأساسية (Cloudflare — موصى بها):** في `wrangler.toml` داخل `[vars]`:

```toml
[vars]
PRODUCTS_SHEET_URL = "https://docs.google.com/spreadsheets/d/e/2PACX-xxxx/pub?gid=0&single=true&output=csv"
```

ثم انشر مرة واحدة: `pnpm build && pnpm deploy:edge`.

بهذه الطريقة يقرأ Cloudflare Worker الشيت على الحافة ويخزّن النتيجة 5 دقائق،
فلا يطلب أي زائر الشيت مباشرة (أسرع، وبلا أي مشاكل CORS).

**طريقة بديلة/إضافية (وقت البناء):** في ملف `.env`:

```
VITE_PRODUCTS_SHEET_URL=https://docs.google.com/spreadsheets/d/e/2PACX-xxxx/pub?gid=0&single=true&output=csv
VITE_WHATSAPP_NUMBER=201000000000
```

تستخدم هذه إذا نُشر الموقع كملفات ثابتة بلا Worker: يقرأ المتصفح الشيت مباشرة.
لو ضُبطت الطريقتان فالأولوية للـWorker والثانية احتياط تلقائي.

> ⚠️ تغيير **الرابط** يحتاج نشرًا واحدًا. أما إضافة/تعديل **المنتجات** فلا تحتاج أي نشر.

## 4) الروتين اليومي (من الهاتف)

1. **صوّر المنتج** بكاميرا الهاتف.
2. **جهّز الصورة بالـAI** باستخدام النص الموجود في عمود `product_prompt`.
3. **ارفع الصورة النهائية إلى Google Drive** (مجلد واحد ثابت للمنتجات مثلًا).
4. **اضبط مشاركة الصورة**: على الملف → Share → General access →
   **Anyone with the link → Viewer** (خطوة إلزامية وإلا لن تظهر الصورة).
5. **انسخ الرابط** (Copy link) والصقه في عمود `image` كما هو — الموقع يحوّله
   تلقائيًا لصيغة عرض مباشرة، ويجرّب صيغة بديلة تلقائيًا إن تعذّرت الأولى.
6. **أضف صفًا جديدًا في الشيت**: `id, name, price, category, description, image, active, sort_order, product_prompt`.
7. خلال ~5 دقائق (أو فورًا بعد ضغط «تحديث» في صفحة الكتالوج) يظهر المنتج على
   **omrantoys.store**. بلا GitHub، بلا Commit، بلا Deploy، بلا API Key.

### عمليات سريعة

- **إخفاء منتج مؤقتًا:** اكتب `FALSE` في `active` (لا تحذف الصف).
- **تغيير سعر:** عدّل خانة `price` فقط.
- **إعادة الترتيب:** غيّر أرقام `sort_order`.
- **منتج بلا صورة بعد:** اترك `image` فارغًا؛ تظهر لوحة بديلة أنيقة لا مربع مكسور.

## 5) ما الذي يحدث تقنيًا (باختصار)

| الطبقة                             | الدور                                                                          |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| `shared/products.ts`               | نوع `Product` + محلل CSV + تحويل الأنواع + روابط Drive + الترتيب + الكاش.        |
| `worker/index.ts` (`/api/products`)| يقرأ الشيت على حافة Cloudflare مع كاش 5 دقائق، ولا يُظهر خطأ للزائر أبدًا.        |
| `server/products.ts`               | نفس المسار في التطوير المحلي (`pnpm dev`) وعلى VPS إن استُخدم.                   |
| `client/src/lib/productsClient.ts` | يجلب `/api/products`، ويحتاط بقراءة الـCSV مباشرة عند الحاجة.                     |
| `client/src/pages/Products.tsx`    | نفس تصميم الموقع: بحث، فلاتر تصنيفات، بطاقات، تفاصيل، واتساب، RTL عربي.           |

الكاش: 5 دقائق على الحافة + 5 دقائق في المتصفح (React Query) — لا طلب لـGoogle
مع كل تفاعل للمستخدم. زر «تحديث» في الصفحة يتجاوز كاش المتصفح فورًا.

إذا تعذّر الوصول إلى Google: تُقدَّم آخر نسخة ناجحة من الكاش، وإن لم توجد
تظهر حالة فارغة محترمة بالعربية + روابط الصفحات الرسمية. لا رسائل خطأ تقنية للزائر.

## 6) اختبار النظام

```bash
pnpm test        # 61 اختبارًا: تحليل CSV، الأنواع، الترتيب، inactive، بلا صورة،
                 # سعر غير صالح، صور Drive، البحث، الفلاتر، التفاصيل، واتساب، الأخطاء
pnpm check       # فحص أنواع TypeScript للتطبيق والـWorker
pnpm build       # بناء الإنتاج
```

تجربة يدوية محليًا بشيت حقيقي:

```bash
PRODUCTS_SHEET_URL="<رابط CSV المنشور>" VITE_WHATSAPP_NUMBER=201000000000 pnpm dev
# ثم: http://localhost:3000/
curl -s http://localhost:3000/api/products | head   # يجب أن يعيد status: "ok"
```

قائمة فحص سريعة على الهاتف بعد النشر:

1. المنتجات تظهر بالترتيب الصحيح. 2. الصور تظهر (بما فيها صور Drive).
3. الأسعار صحيحة. 4. رقائق التصنيفات تفلتر. 5. البحث يعمل.
6. تفاصيل المنتج تفتح وتُغلق. 7. زر واتساب يفتح رسالة تحوي اسم المنتج.
8. منتج `active = FALSE` غير ظاهر. 9. منتج بلا صورة يظهر بلوحة بديلة.
10. العرض سليم على Android وiPhone وسطح المكتب.

## 7) الخطوات اليدوية المطلوبة منك (مرة واحدة)

1. إنشاء الشيت بالأعمدة التسعة أعلاه.
2. نشره كـCSV (القسم 2).
3. لصق الرابط في `wrangler.toml` (أو `.env`) ونشر الموقع مرة واحدة (القسم 3).
4. ضبط `VITE_WHATSAPP_NUMBER` (أو `whatsappNumber` في
   `client/src/lib/socialEmbeds.ts`) ليظهر زر الطلب عبر واتساب.
5. لكل صورة على Drive: **Anyone with the link → Viewer**.

بعد ذلك: لا شيء سوى إضافة صف في الشيت لكل منتج جديد.
