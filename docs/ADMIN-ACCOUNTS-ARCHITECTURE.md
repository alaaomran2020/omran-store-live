# لوحة الإدارة وحسابات العملاء وصلاحيات RBAC — المعمارية والحدود التشغيلية

تاريخ الإنشاء: 2026-09-13
النطاق: لوحة `/admin/dashboard` وصفحات الإدارة، تطبيق `/account/*` للعملاء،
نموذج الأدوار RBAC، بوابة OTP، المفضلة، مركز جودة الكتالوج، سجل التدقيق.

هذه الوثيقة جزء من عقد المعمارية في
[`CURRENT-ARCHITECTURE.md`](./CURRENT-ARCHITECTURE.md) وتخضع لنفس قاعدة
Change Control: أي تغيير في الحدود الأمنية الموثقة هنا يجب أن يُراجَع في نفس
طلب السحب مع `scripts/integration-audit.mjs`.

## 1. ما الموجود الآن في الإنتاج (واجهة ثابتة + منطق مشترك آمن)

المتجر ثابت بالكامل (Vite SPA على Cloudflare Pages، بلا زمن تشغيل خادمي). كل ما
يلي يعمل الآن دون أي بنية تحتية إضافية:

### 1.1 لوحة الإدارة (تحت بوابة Cloudflare Access على `/admin*`)

| المسار | الصفحة | مصدر البيانات |
|---|---|---|
| `/admin/dashboard` | مركز عمليات: KPIs، صحة الكتالوج، الحالة النشر، POP UP مقابل عمران، مقاييس واتساب، QA، إجراءات سريعة | الكتالوج المُجمّع + البوابات الاختيارية بحالة صادقة |
| `/admin/products` | قائمة المنتجات (بحث/فلاتر/فرم، 3000+ منتج عبر فهرسة كسولة) | الكتالوج المُجمّع |
| `/admin/products/:id` | محرر المنتج + حزمة تعديل TSV موقّعة/نسخ/تنزيل | الكتالوج + حزمة تغيير |
| `/admin/categories` | خريطة التصنيفات والفئات غير المربوطة (عمران وPOP UP منفصلان) | الكتالوج + `shared/taxonomy` |
| `/admin/inventory` | حالة التوفر الاشتقاقية فقط (متاح/غير متاح/طلب مسبق/غير معروف) | الكتالوج |
| `/admin/quality` | مركز جودة QA: صور مفقودة/مستضافة على Drive، حقول ناقصة، حالات نشر | `shared/catalogQuality` |
| `/admin/content` | المحتوى والإعلانات والفروع والمصدر المنفصل لـPOP UP | `shared/storeContent` |
| `/admin/whatsapp` | مقاييس واتساب المقروءة (بحالة live/not_configured) | بوابة قراءة اختيارية |
| `/admin/reports` | تقارير اشتقاقية قابلة للتصدير (CSV/TSV بصيغ آمنة للمعادلات) | الكتالوج |
| `/admin/customers` | سجل العملاء (بحالة البوابة) | بوابة قراءة اختيارية |
| `/admin/users` | إدارة الموظفين ودعواتهم وأدوارهم (إجراءات موقّعة + حزم تغيير) | بوابة قراءة/كتابة اختيارية |
| `/admin/audit-log` | سجل التدقيق (بحالة البوابة) | بوابة قراءة اختيارية |
| `/admin/settings` | حالة البوابات والمصادر وسياسات النشر | ثابت + فحص البيئة |
| `/admin/product-intake` | إدخال المنتجات (موجود سابقًا، محفوظ تحت نفس البوابة) | بوابة Make الموحّدة |
| `/admin/vip-operations` | عمليات VIP اليدوية (موجود سابقًا) | حزم صفوف PENDING |

كل قراءة تشغيلية تُرجع حالة واضحة لا تخفي الوضع:

- `live` — البيانات وصلت فعلاً من البوابة وطابقت العقد.
- `not_configured` — البوابة غير منشورة؛ الواجهة تعرض حالة فارغة صادقة بلا أرقام
  مختلقة.
- `error` — فشل عابر مع رسالة.

الكتابة عبر `VITE_ADMIN_ACTIONS_WEBHOOK_URL` اختياريًا؛ عند غيابه تُنتج الصفحات
**حزمة تعديل TSV موثّقة** (نسخ/تنزيل، صيغ آمنة من حقن المعادلات) بدل تزوير نجاح
محلي في الكتالوج. الكتالوج نفسه لا يُعدَّل في المتصفح أبدًا.

### 1.2 حساب العميل (`/account/*`)

| المسار | المحتوى |
|---|---|
| `/account/login` | دخول بالموبايل المصري + OTP (خطوتان، عدّاد صلاحية من الخادم، إعادة إرسال 45 ثانية، سقف محاولات) |
| `/account/profile` | الاسم الكامل والبريد الاختياري؛ الموبايل للقراءة ويُغيَّر عبر OTP جديد فقط |
| `/account/addresses` | عناوين العميل (قراءة/إضافة عبر البوابة الآمنة فقط) |
| `/account/wishlist` | المفضلة (انظر 1.4) |
| `/account/vip` | حالة برنامج VIP بلا بيانات عضوية مخترعة + رابط صفحة البرنامج |
| `/account/settings` | مسح البيانات المحلية + خروج يُبطل الجلسة على الخادم |

قبل تفعيل بوابة OTP: صفحة الدخول **تفشل بأمان** ببطاقة صادقة («تسجيل الحسابات
بالـOTP قيد التفعيل») + قناة واتساب بديلة. لا رمز وهمي ولا قناة تجاوز مخفية.

### 1.3 نموذج الصلاحيات RBAC (`shared/rbac.ts`)

الدور المركزي الوحيد هو `can(principal, permission)`. المصفوفة:

| الدور | الصلاحيات |
|---|---|
| `VIEWER` | قراءة كل صفحات الإدارة فقط |
| `CONTENT_EDITOR` | + `content:update` |
| `INVENTORY_STAFF` | + `inventory:update` |
| `CATALOG_MANAGER` | + إدارة المنتجات والتصنيفات، النشر/الأرشفة، `quality:update` |
| `ADMIN` | + إدارة المستخدمين (لا يمكنه منح دور OWNER) |
| `OWNER` | كل شيء، بما فيه إدارة الأدوار والمالكين |

حمايات مدمجة ومختبرة: آخر مالك نشط لا يمكن تعطيله/تخفيضه؛ لا يمكن تغيير دور
النفس أو تعطيل النفس؛ `CUSTOMER` وأي حالة غير `ACTIVE` صلاحياتها صفر؛ أي
`principal` خارج نطاق `EMPLOYEE` يُعامَل بصلاحيات صفرية.

تح resolution الهوية داخل الواجهة (للعرض فقط): هوية Cloudflare Access
(`/cdn-cgi/access/get-identity`) → مطابقة دليل الموظفين من البوابة → بذرة الملاك
من `VITE_OWNER_EMAILS` (غير سرية) → أقل امتياز `VIEWER`. المستخدمون
`INVITED/SUSPENDED/DISABLED` يُحجبون.

> **حد حاسم:** فحوصات الواجهة للعرض والتحكم في الوصول UI فقط. المنفذ النهائي
> للصلاحيات هو الخادم (القسم 2.3). لا شيء في هذا المستودع يعتبر حاجز أمان بحد
> ذاته ضد مستخدم يصمّم طلبًا بنفسه.

### 1.4 المفضلة على الجهاز (`client/src/lib/wishlist.ts`)

- تُحفظ **معرّفات المنتجات فقط** تحت `omran.wishlist.ids.v1` (سقف 500، تحقق من
  سلامة JSON، بلا أي توكن أو بيانات هوية).
- زر القلب في نافذة تفاصيل المنتج (نسخة واتساب ونسخة بدون واتساب، ديسكتوب وموبايل)
  وصفحة `/account/wishlist` تحل المعرّفات مقابل **الكتالوج العام المنشور فقط**
  (`active && PUBLISHED && PASS`)؛ المنتج غير المنشور يظهر كـ«غير متاح حاليًا».
- مزامنة الأجهزة تُفعَّل مع حساب العميل الخادمي (القسم 2.6)؛ حاليًا المفضلة
  صراحةً على الجهاز فقط، ولا توصف بأنها مزامنة.

### 1.5 سياسة OTP المشتركة (`shared/otp.ts`)

السياسة الكاملة معرّفة ومختبرة في مكان واحد ليطبّقها الموثوق-الخادم:

- رمز 6 خانات من مولّد أرقام عشوائية آمن (CSPRNG) مع إلغاء تحيّز البواقي.
- صلاحية 5 دقائق، سقف 5 محاولات خاطئة، إعادة إرسال بعد 45 ثانية.
- سقف 5 طلبات/رقم و20 طلبًا/عنوان IP خلال 15 دقيقة.
- يُخزَّن فقط `SHA-256(code:challengeId)`؛ مقارنة ثابتة الزمن؛ الرمز للاستخدام
  مرة واحدة؛ العميل لا يرى الرمز أبدًا.

### 1.6 فصل بيانات POP UP

POP UP (Gifts & Balloons) له بادئة `POP-*` وحقل `sourceBrand`، وفي كل صفحة
إدارية ورسم بياني وفلتر يُحسب ويُعرض منفصلًا عن عمران تويز. لا تختلط المقاييس
أو التصنيفات أو المحتوى بين العلامتين.

## 2. البنية التحتية غير الموجودة — ما توقّف، ولماذا، والحد الأدنى الآمن

القاعدة المعتمدة: لا أرقامًا ولا حسابات ولا جلسات مخترعة في كود ثابت. البنود
التالية واجهتها مبنية وعقودها جاهزة، لكن تفعيلها يحتاج مكوّنًا موثوقًا خادميًا.
نشر أيٍّ منها لا يحتاج VPS ولا قاعدة بيانات مدارة ذاتيًا (راجع البدائل أدناه).

### 2.1 زمن تشغيل OTP (توليد/إرسال/تحقق/حدود معدل)

- **الموجود:** عميل `client/src/lib/auth/authClient.ts`، سياسة `shared/otp.ts`،
  واجهة `OtpInput` وواجهة الدخول، حالات أخطاء كاملة، Fail-Closed على
  404/501/فشل اتصال.
- **الناقص:** طرف موثوق يملك سرًّا لإرسال الرسائل (مزود SMS/واتساب للأعمال)
  ويخزّن التحديات ويطبّق الحدود.
- **لماذا لا يُحل في SPA:** أي سر إرسال في كود المتصفح يُسرق؛ توليد الرمز في
  المتصفح = رمز وهمي؛ حدود المعدل في المتصفح يلغيها المهاجم بسهولة.
- **الحد الأدنى الآمن:** Cloudflare Pages Function تحت `/api/auth/*` (أو Apps
  Script Web App بملكية المتجر، أو Make سيناريو) مع مخزن KV/Sheet:
  - `POST /otp/request` يطبّع الرقم (`shared/mobile.ts`)، يولّد الرمز عبر
    `crypto`, يخزّن بصمته + الطوابع الزمنية، يرسله عبر مزّود، يعيد فقط
    `{challenge_id, expires_in, resend_in}`.
  - `POST /otp/verify` يتحقق ثابت الزمن، يستهلك المحاولة، يضبط شطيرة الجلسة.
  - عقدا الطلب/الاستجابة موثقان في أعلى `authClient.ts`.
- **ما يعمل الآن:** لا دخول؛ بطاقة صادقة + واتساب بديل. لا يوجد وضع تجاوز.

### 2.2 جلسات HttpOnly الآمنة

- **الناقص:** إصدار/التحقق/إبطال شطيرة `HttpOnly; Secure; SameSite=Lax`
  منفصلة لكل نطاق (شطيرة عميل لا تُرسَل لمسارات الإدارة، والعكس عبر اسم
  وكاشف مسار مختلفين).
- **لماذا:** جلسة في localStorage/sessionStorage قابلة للسرقة عبر XSS وتجعل
  أدوار العميل «موثوقة من العميل» — ممنوع صراحةً.
- **الحد الأدنى:** نفس Pages Function يُصدر توقيعًا (HMAC بسر خادمي) أو مرجع
  جلسة في KV؛ `GET /api/auth/session?domain=...` يطابق العقد في `shared/identity`
  ويعيد `CustomerSessionResult`؛ `POST /logout` يُبطل المرجع فورًا.
- **ما يعمل الآن:** حارس `/account/*` يرى لا جلسة ويعرض الدخول؛ لا شيء يُخزَّن
  محليًا.

### 2.3 فرض الصلاحيات على الخادم + دليل الموظفين الدائم

- **الناقص:** مخزن دليل الموظفين (الدور، الحالة، الموبايل الموثّق، البريد)
  ومتحقق خادمي لكل إجراء كتابي يستدعي نفس `can(principal, permission)` من
  `shared/rbac.ts` (الكود مشترك ويُستورد كما هو في Pages Function/أي بيئة JS).
- **لماذا:** حجب الأزرار في الواجهة ليس حدًّا أمنيًّا؛ البوابة يجب أن ترفض
  الطلب غير المصرّح بصرف النظر عمن أرسله.
- **الحد الأدنى:** ورقة `Employees` (أو KV) يكتب فيها المالك/الأدمن عبر البوابة
  فقط؛ صفوف `Employee` حسب `shared/identity`؛ كل `POST` إداري يتحقق من شطيرة
  Cloudflare Access + الدور قبل التنفيذ ويسجل حدث تدقيق.
- **Cloudflare Access يبقى الحارس الخارجي الإلزامي على `/admin*`**؛ OTP للموظفين
  طبقة تحقق ثانية وربط موبايل، لا بديل عن Access.

### 2.4 مخزن سجل التدقيق

- **الموجود:** `shared/audit.ts` (تطبيع الحدث، تسلسل آمن) + صفحة `/admin/audit-log`
  + عميل قراءة بعقد `AuditRecord`.
- **الناقص:** مخزن إلحاقي غير قابل للتعديل من العميل (ورقة `Audit_Log`/KV مع
  سجل ربما دوري للتصدير). كل محاولة (ناجحة/مرفوضة) من البوابة تُسجَّل: الفاعل،
  الإجراء، الهدف، البيانات الوصفية، الطابع الزمني.
- **ما يعمل الآن:** حالة `not_configured` صادقة؛ حزم التغيير اليدوية تتضمن
  ترويسة تدقيق (المصدر: «حزمة يدوية من اللوحة»).

### 2.5 ملفات العملاء والعناوين

- **الناقص:** مخزنا `Customers` و`Customer_Addresses`، ونقطة
  `POST /api/auth/account/action` (ينفذها العميل صاحب الجلسة فقط؛ تحقق ملكية
  السجل في كل طلب؛ تسجيل/تحديث الاسم، البريد، العناوين).
- **العقد:** أنواع `Customer`, `CustomerAddress`, `CustomerSessionResult` في
  `shared/identity.ts`؛ العميل في `authClient.postCustomerAction` يفشل بأمان
  على 404/501 (NOT_CONFIGURED) ويعيد 401 كـ«انتهت الجلسة».
- **ما يعمل الآن:** الدخول والملف والعناوين تعرض الحالة الصادقة؛ لا حفظ محلي
  لبيانات الهوية إطلاقًا.

### 2.6 الجرد الرقمي (كميات وعتبات نقص)

- **الناقص:** مصدر كميات موثوق يملكه المتجر (ورقة جرد/نظام مخزني) به عدد فعلي
  وعتبة لكل SKU، وتمييز «غير معروف» عن «متاح».
- **القاعدة المصممة:** التعداد الحالي هو
  `available/unavailable/preorder/unknown` فقط؛ **`unknown` لا يُعامَل كمتاح
  أبدًا** ولا يُشتق رقم مخزون من بيانات التسويق.
- **ما يعمل الآن:** `/admin/inventory` يعرض التوزيع الاشتقاقي لحالات التوفر
  وروابط الاستفسار عبر واتساب؛ الكتابة (تغيير حالة/كمية) حزمة يدوية موثّقة حتى
  يوجد المصدر.

### 2.7 تحليلات واتساب المقروءة

- **الموجود:** ضغطات واتساب من الواجهة تُرسل بالفعل إلى دفتر أول-طرف عبر بوابة
  Make الموحّدة (`persistStorefrontEvent`)؛ صفحة `/admin/whatsapp` وتبويب
  اللوحة يحللان الأرقام إن وصلت.
- **الناقص:** سيناريو/قراءة تجميعية على البوابة تُرجع عقد
  `WhatsAppMetrics` (الإجمالي، اليوم، آخر 7 أيام، الترند، أعلى المنتجات/
  التصنيفات) — والمقاييس التشغيلية (زمن الرد، نسبة التحويل لحجز مؤكد) تحتاج
  مصدرًا إضافيًا يدويًا أو تسجيلًا من الموظفين؛ لا تُقدَّر من عدد الضغطات.
- **ما يعمل الآن:** بث الضغطات حي؛ القراءة تُظهر `not_configured` بلا أرقام.

### 2.8 ترتيب التفعيل المقترح

1. Pages Function `/api/auth/session|logout` + شطيرتان → 2.2.
2. `/api/auth/otp/*` مع مزود إرسال واحد وKV → 2.1 (يبدأ بالعملاء).
3. أوراق Employees + Customer/Audit مع تحقق `can` خادمي على كل كتابة → 2.3/2.4/2.5.
4. قراءة تجميع واتساب → 2.7؛ مصدر الجرد → 2.6.
حتى ذلك الحين، كل ميزة متوقفة تُبقي الواجهة في حالتها الصادقة ولا تُخفي النقص.

## 3. متغيرات البيئة

| المتغير | الغرض | الافتراضي |
|---|---|---|
| `VITE_OWNER_EMAILS` | بريد/قائمة بريد مفصولة بفواصل لبذرة دور OWNER داخل الواجهة (غير سرية؛ لا يلغي تحقق الخادم) | فارغ → الكل VIEWER |
| `VITE_AUTH_API_BASE` | قاعدة بوابة OTP/الجلسات Same-origin | `/api/auth` |
| `VITE_ADMIN_ACTIONS_WEBHOOK_URL` | نقطة استلام الإجراءات الإدارية الموقّعة | فارغ → حزم TSV يدوية |

يُمنع عمدًا: `VITE_ADMIN_AUTH_URL` (يفحصها integration-audit ويرفضها)، أي توكن
أو كلمة مرور أو سر مزود في متغيرات `VITE_*`.

## 4. قواعد لغوية وتشغيلية ملزمة للوحات

- العربية المصرية RTL: «عربيات» وليس «سيارات»، «عرايس» وليس «دمى».
- اسم العلامة «عمران» (وليس «أمران»)؛ تجنّب مصطلح «ولاء» في سياق برنامج العملاء.
- العملة جنيه مصري EGP؛ المنتج بلا سعر موثّق يُعرض «استفسار» ولا يُخمَّن رقم.
- لا بيانات زائفة: لا عملاء تجريبيين، لا طلبات، لا إيرادات، لا مقاييس مخترعة؛
  اللوحة مركز **تشغيلي** (كتالوج، جودة، توفر، ضغطات واتساب) وليست تقرير مبيعات.
- POP UP دائمًا مصدر/فلاتر/رسوم منفصلة.

## 5. بوابات الجودة

العقد في CI: `node scripts/integration-audit.mjs` ثم
`pnpm lint && pnpm check && pnpm test && pnpm build`.
الأصول الجديدة مشمولة باختبارات: RBAC (`shared/rbac.test.ts`)، سياسة OTP
(`shared/otp.test.ts`)، الجودة (`catalogQuality.test.ts`)، المقاييس
(`adminMetrics.test.ts`)، التدقيق، تطبيع الموبايل، فهرس كتالوج الإدارة
(`adminCatalog.test.ts`، أداء 3000+ منتج)، المفضلة، مكوّن إدخال OTP.
